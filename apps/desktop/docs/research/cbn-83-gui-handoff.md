## Two different selection contracts

**Board frames are live context.** Each prompt lists every frame's ID, name, HTML path, dimensions and position, plus sections, selected IDs and the frame open in Preview. Selection scopes the next request without an explicit attachment action. `promptBoard()` reads current board state, and `runTurn()` calls it when constructing the prompt, after the turn has waited for its agent and edit slot. Steering also calls it then. The queued payload captures preview picks and viewport, but does not freeze the board context. This means a queued request's board selection can follow a later selection; it is not a durable design reference. [Prompt contract](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L102-L133), [state read](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/tab.ts#L1388-L1400), [prompt dispatch](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/chat.ts#L1680-L1764), [queue capture](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/chat.ts#L1585-L1627).

**Preview picks are captured context.** Element picks contain page URL, viewport, tag, selector, text, HTML, bounds, computed CSS, component stack, optional source location and crop screenshot. Area picks contain the chosen rectangle, screenshot and surrounding element/source. Prompts deliver this data in separate fenced blocks, followed by images when the agent supports them. Source locations are hints to confirm against files. [Types](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/shared/types.ts#L749-L815), [prompt assembly](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L183-L233), [element and area descriptions](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L373-L430).

## Composer, queue and history

The composer shows each preview pick with a thumbnail, identity and removal button; hovering highlights its target in the page. Accepting a send or queue entry clears those picks. Sent messages retain identity chips. An accepted queue entry holds the captured picks and viewport, and pending entries are serialized with full selection crops for restart. [Composer](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/renderer/src/chat/composer.tsx#L578-L634), [message chips](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/renderer/src/chat/turn-view.tsx#L260-L282), [queue persistence](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/chat.ts#L2790-L2826), [saved queue schema](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/history.ts#L33-L82).

Completed turns preserve captured HTML/styles/source metadata, but strip `screenshot` from their picks. Their before/after preview images are live-session-only and removed from saved history. Reference-image attachment thumbnails are a separate field. Gui's normal pick chip therefore survives reload as identity/context, not as a retained screenshot-backed revision. [Turn creation](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/chat.ts#L1504-L1535), [image stripping](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/chat.ts#L2849-L2853), [history serialization](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/history-format.ts#L16-L23).

## Revisions and missing designs

The inspected `PromptBoard` and `Picked` contracts have no immutable canvas/frame revision address. `canvas_screenshot` takes a frame ID, not a historical revision. Removing frames filters their IDs out of current selection and clears an affected open frame; external file reconciliation does likewise. I found no changed-design warning or refresh action on the inspected pick-chip path. This does not prove no such feature exists elsewhere, but these handoff paths do not provide CBN-83's pinned-reference semantics. Thumbnail capture versions and chat transport revisions serve cache/stream consistency, not design attachment history. [Board prompt](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L102-L133), [screenshot schema](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/mcp-board-tools.ts#L199-L222), [deletion](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/board-session.ts#L600-L628), [reconciliation](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/board-session.ts#L890-L909).

## Exploration, project code and verification

Canvas instructions describe standalone HTML explorations, with each alternative in a new named frame and originals preserved. Project instructions instead ask for minimal source edits using existing conventions. The explicit **Turn into Project** action makes a new Vite project from a frame's HTML and copied assets; it does not reconstruct React components or apply the design into an existing app. [Separate instructions](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L25-L31), [canvas instructions](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L68-L82), [explicit handoff](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/index.ts#L563-L587), [new project implementation](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/new-project.ts#L7-L46).

Agents are instructed to screenshot each changed frame, compare and revise, and open it for interaction checks. Project guidance asks for a source-edit/hot-reload/screenshot loop, interactive-state checks, narrow viewports and console checks. These are prompt instructions and available tools, not proof that an agent obeyed or that a runtime check passed. [Verification guidance](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L39-L55), [canvas checks](https://github.com/brijr/gui/blob/4238191da2647b3252120edc1cdcc301e9c166a5/src/main/prompt.ts#L73-L81).

## Carbon decision

Borrow Gui's explicit dimensions, ordered picks, visual composer feedback, separate exploration/project instructions and preview verification loop. Keep Carbon's agreed attachment contract: **Add to chat** captures a specific selection without sending; draft, queue and transcript retain that exact revision and preview. Show changed/unavailable status and refresh only on request. Do not copy Gui's implicit live board context for an explicitly attached design, or its removal of historical screenshots. Reusing app components and tokens belongs to Carbon's project-code handoff; Gui's Vite export is a different product action.
