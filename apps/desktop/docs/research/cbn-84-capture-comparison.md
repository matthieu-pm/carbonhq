# CBN-84 Capture comparison

Checked on November 18, 2026 against Paper's public documentation and live MCP tool list, and Gui's documentation and source. The browser extension and desktop workflows were not exercised.

## Paper

Paper Snapshot is the closest precedent for editable capture. The browser extension highlights an element, lets the user refine the target with Up/Down, and copies it on click or Enter. Command-Enter captures the full page. The user then pastes the result as editable layers into a chosen Paper file on desktop or web. The paste step determines the destination. [Snapshot quick start](https://paper.design/snapshot-extension), [Paper build log](https://paper.design/build-log), [extension listing](https://chromewebstore.google.com/detail/paper-snapshot/lidfahaahiogmnlccifabccgplofocck).

Paper documents a real asset failure mode. Local images require cross-origin access from the Paper editor. Its build log describes better capture of form fields, tables and overlaps, plus preservation of OpenType features. The sources reviewed leave the handling of unsupported regions and original screenshots unspecified. [Local image guide](https://paper.design/docs/support/snapshot-local-images), [Paper build log](https://paper.design/build-log).

The live Paper MCP tool list exposes `write_html` for inserting editable nodes into a chosen file and parent. `get_jsx`, `get_fill_image`, `get_screenshot` and `export` operate on designs already in Paper. The inspected MCP has no Snapshot tool or single-file browser capture export. [Paper MCP documentation](https://paper.design/docs/mcp), [HTML import documentation](https://paper.design/docs/paste/html).

## Gui

Source reviewed at `38f46dc5f5d98269f0363b234488357308086497`.

- **Where the result goes.** Gui's Design mode outlines live elements. Clicking an element or dragging an area adds a pick to the next chat message. Element picks carry HTML, computed styles, bounds and source hints. Image-capable agents also receive the screenshot. The preview camera can copy or save a picture or attach it to chat. A separate `canvas_create_frame` call writes a supplied HTML page to the current canvas and places it beside named frames, or beyond all existing frames. [Design mode and camera](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/docs/using-gui.md#L19-L21), [pick prompt](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/prompt.ts#L203-L220), [element context](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/prompt.ts#L373-L410), [frame creation](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/mcp-board-tools.ts#L114-L138).
- **Editable content and image references.** Gui stores authored frames as standalone HTML files. Its public website reference flow optionally saves a JPEG in `assets/`, then the agent creates an HTML frame containing an `<img>` that points to it. The reviewed tools expose no automatic live DOM reconstruction or region-by-region fallback. The public website flow uses a fresh signed-out browser session. [Canvas guidance](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/prompt.ts#L68-L79), [website screenshot](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/mcp-board-tools.ts#L223-L276).
- **Agent capture and export.** MCP `preview_screenshot` takes a selector, viewport width or full-page flag and returns an image with dimensions and any truncation. It exposes no output path. Full-page preview screenshots are capped at 8,000 CSS px tall. `canvas_screenshot_url` reports its separate 12,000 px cap and optionally saves the image asset. An existing frame can be saved as HTML or exported as PNG through the UI. The `gui` shell command opens a folder, and optional external MCP exposes preview screenshots and frame creation. The reviewed interfaces have no single capture export containing editable layers, assets, source context and a reference screenshot. [Preview screenshot](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/mcp-preview-tools.ts#L424-L460), [website screenshot](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/mcp-board-tools.ts#L223-L276), [frame export menu](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/tab.ts#L4578-L4593), [shell command](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/docs/using-gui.md#L13-L17), [external MCP](https://github.com/brijr/gui/blob/38f46dc5f5d98269f0363b234488357308086497/src/main/outside-mcp.ts#L40-L78).

## Recommendation for Carbon

- In the browser pane, use Paper's direct element and full-page pick. Add the result to the project's selected canvas, then reveal the new frame. Ask for a canvas only when there is no selection. The app can supply the explicit destination that Paper gets from Paste.
- Retain Gui's visual and source context with the frame. Keep reconstructable layers editable, label image fallbacks for unsupported regions, and retain the original screenshot. Report missing resources and truncation beside the capture. If only the screenshot can be saved, label the whole frame **Image reference**.
- Give the CLI an explicit artifact destination. `carbon browser capture [selector] --to <file>` should write a self-contained copy with layers, assets, original screenshot, source hints and warnings. Adding a frame to a board should be a separate explicit action.
