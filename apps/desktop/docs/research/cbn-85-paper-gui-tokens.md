# Paper and Gui token workflows for CBN-85

Checked 18 November 2026 against Paper's public documentation, its live MCP schema and the distributed Snapshot extension, and Gui `main` at [`87fb7b30`](https://github.com/brijr/gui/commit/87fb7b30a69de56716ac5458853afa0e77c2d1c9). The Snapshot extension and Gui findings come from static inspection.

## Paper

- **Discovery and import.** The user points an agent at a codebase and asks it to create Paper tokens from CSS variables over MCP. The agent can also create them from a Canvas design. Paper stores the results in the design file. The Theme tab lists and edits tokens, and Properties offers named tokens on supported fields. The documented types include color, radius, spacing, containers, breakpoints and typography. [Token guide](https://paper.design/docs/tokens)
- **Updates and scope.** Changing an imported token in Paper updates every property linked to it in that file. Detaching keeps the property's current value. Tokens can be copied into another Paper file or exported to CSS. Copies are independent. The guide lists multiple theme modes on the roadmap. The documented workflow leaves source-format discovery and worktree selection to the agent. [Token guide](https://paper.design/docs/tokens), [build log](https://paper.design/build-log)
- **Agent reads and writes.** The live `get_tokens` schema offers filters and JSON, vanilla CSS `:root`, or Tailwind v4 `@theme` output. The live MCP guide directs agents to use `var(...)` and re-read tokens when their content hash changes. `set_tokens` exposes explicit updates, renames and deletions. These operations address the Paper file's token definitions. [MCP setup and workflows](https://paper.design/docs/mcp)
- **Browser capture.** Snapshot copies an element as editable HTML. The distributed extension's normal capture path measures a fixed list of computed properties and serializes them as inline styles. Its clipboard helper writes HTML, with no separate token provenance payload. The code's CSS rule walk handles viewport media rules before measurement. This establishes what the extension sends. Paper's paste handling was not exercised. REA inspected `background.js` and `offscreen.js` in version `0.4.13`. The CRX SHA-256 is `eb691aab1fdcb16bd2ee1c4f263d655d967de7b241f402462fa022d72f3669fe` and the REA evidence ID is `ev_d25d6fb0ccb0113f0a144b87e87ad0dfde22c8bc660ed79c73c4d1d865987185`. [Snapshot guide](https://paper.design/snapshot-extension), [distributed extension](https://chromewebstore.google.com/detail/paper-snapshot/lidfahaahiogmnlccifabccgplofocck)

## Gui

- **Project and canvas.** The project tab has a concrete open folder. Project agents edit the source and follow its styling conventions. Canvas frames are standalone HTML files in a canvas folder. Agents can use an optional `assets/brand.md` as design guidance. The canvas manifest and board tools expose frames and layout. The inspected contracts have no project token catalog, token refresh command, or token-specific theme/worktree chooser. [Open project](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/tab.ts#L944-L962), [project styling guidance](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/prompt.ts#L25-L30), [canvas guidance](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/prompt.ts#L68-L81), [board tools](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/mcp-board-tools.ts#L11-L21), [manifest](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/shared/board.ts#L138-L145)
- **Browser inspection.** A pick gives the agent raw HTML, selected computed styles, a crop and optional source location. An inline variable can appear in the HTML. The computed style map holds property values and has no declaration-to-token link. The source resolver uses the open project root and marks approximate locations so the agent can check the original file. [Inspector output](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/inspector.ts#L453-L503), [computed style reader](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/inspector.ts#L786-L809), [source resolver](https://github.com/brijr/gui/blob/87fb7b30a69de56716ac5458853afa0e77c2d1c9/src/main/source-resolver.ts#L124-L171)

## Implications for Carbon

- Start with CSS custom properties, including Tailwind v4 `@theme` and scoped overrides. Show the declaration's file and selector or theme scope. Let agents read the project's other formats when needed. Paper supplies the useful UI pattern of a token list and names at the property, while Gui's source hints show the value of recording provenance.
- Use the selected Canvas chat session's worktree as the source, with the attached project folder as the fallback. Display the resolved folder so the user knows which checkout Refresh will read. Keep a separate worktree picker out of v1 unless users need cross-worktree comparison.
- Preserve a proven token name alongside each captured value. Keep computed-only properties unlinked. Refresh re-reads the project catalog and can flag a token missing from that source. The captured value keeps the frame inspectable and the handoff carries the verified token name so the agent can look for it in the target project.
