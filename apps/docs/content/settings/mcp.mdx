MCP servers give agents tools and access to services. Settings → **MCP** manages one list for every agent launched by Carbon.

Carbon finds existing servers in your agents' configuration automatically. You do not need to import or review them. Their original files stay intact for agents you run in a terminal. Existing project trust still applies to project configuration.

Open Settings with `⌘,`. You can change that shortcut in Settings → Shortcuts.

## Add a server

1. Click **Add server**.
2. Under **Available in**, choose **Every project** or an attached project.
3. Enter a **Name** and choose a **Type**.
4. For **Local command**, enter the executable, one argument per line, and any environment variables. For **HTTP** or **SSE**, enter the URL and any headers.
5. Click **Add server**.

Environment values and headers are masked. Use the eye button to check a value.

## Sign in once

If a server needs authentication, click **Sign in** beside it. Complete sign-in in your browser. Carbon keeps the waiting state visible until sign-in finishes.

That sign-in covers every agent in Carbon. You do not need to sign in separately through each agent. API keys and other static credentials can be supplied through the server's headers or environment variables.

Some services only accept approved MCP clients. If a service refuses Carbon before the browser opens, Carbon needs approval from that service before sign-in can work.

Figma has an automatic fallback through the installed Codex CLI. Carbon reuses your existing Codex MCP login, so signing out of Figma in either Carbon or Codex affects both. This connection needs Codex 0.169.0 or later and runs no model turn. You can keep using any agent in Carbon.

The Figma fallback supports tools and resource reads. Upstream server instructions and MCP prompts are unavailable through this connection. Your agent's normal tool permissions still apply. Cancelling a call closes that chat's connection; Figma may continue work it has already started.

Carbon's issue-tracker connection is separate. See [Issues](/settings/issues).

## Each chat stays separate

Each chat gets its own connection to each server. A browser or working directory used in one chat stays separate from another chat. Repeated calls in the same running chat reuse that connection.

Server and tool names stay the same. You can mention a server with `$` in the composer, and existing agent permission rules can still name it.

## Read the status

The list appears first, then connection checks fill in. Click **Refresh** to check again.

| Status | Meaning |
|---|---|
| **Connected** | Carbon reached the server. |
| **Needs sign-in** | Click **Sign in** to connect it for every agent. |
| **Failed to connect** | Check the server's command, URL or credentials. |
| **Off** | The server is disabled. Use its menu to turn it on. |

A connection that fails during a session also produces a notice in that chat.

## Edit, disconnect or remove

Open a server's **⋯** menu to edit it, turn it on or off, sign out, or remove it. New sessions pick up the change. Removing an automatically discovered server does not import it again.

This page manages the servers on **This Mac**. Servers supplied by an agent's own plugins remain managed by that agent.
