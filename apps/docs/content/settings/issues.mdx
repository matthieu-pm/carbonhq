Carbon reads and creates issues in Linear and GitHub. Describe a new issue in chat, review the draft, then create it. You can also browse existing issues, change status and priority, tag issues into a prompt with `#`, and see a session's linked issues in its right panel.

## Connect a tracker

Connecting happens on the Issues page. Click **Issues** in the navigation rail, or press `⌘I`.

At the top left of the page are two marks, Linear and GitHub. Click the one you want. If it is not connected yet, the page shows how to connect it.

### Linear

<Steps>
  <Step title="Make a key">
    Click **Create a key in Linear** to open Linear's security settings, and create a personal API key. Read and write access lets you create issues and change status and priority from Carbon. A read-only key lets you browse issues.
  </Step>
  <Step title="Paste it">
    Paste the key into the field (it starts `lin_api_`) and press **Connect**. Carbon checks the key with Linear before saving it.
  </Step>
</Steps>

The key is saved in `~/.carbon/credentials.json`, readable only by your user. To remove it, go to Settings → Integrations → Issue tracker and press **Disconnect**. Sessions keep the issues they are tagged with.

The key supports Carbon's issue screens and the [CLI's Linear comment and status commands](/cli/issues). It does not connect your agent's own tools to Linear. For the agent to read full issues and manage them through MCP, add Linear's MCP server through [Settings → MCP](/settings/mcp), then sign in through that agent.

### GitHub

Carbon reads GitHub issues through the `gh` CLI and stores no GitHub credential of its own.

1. If you don't have `gh`, install it: `brew install gh`.
2. Run `gh auth login` in a terminal. You can also sign in from Settings → Accounts → GitHub, which opens Terminal for you.
3. Back on the Issues page, press **Check again**.

If `gh` is still missing or signed out, the page stays as it is. Sign out with `gh auth logout` in your own terminal.

## The Issues page

The page fills the main column. It is not a session, and the right panel is hidden while it is up.

Its sidebar contains **New issue**, **Search**, and **Saved views**. Search focuses the current list's search field. **Assigned to me** and **Created** stay on the list itself.

### Create an issue

1. Click **New issue** in the Issues sidebar. Carbon opens the regular Tasks composer with an editable starter prompt.
2. Add details about the bug or idea and choose an agent and model. The prompt stays unsent until you send it, creating a normal conversation in the task list.
3. The agent's draft appears in an inline **Review issue** card. Edit its title and Markdown description, or send follow-up messages to refine it.
4. Check the tracker and destination: a Linear team and optional project, or a GitHub repository. The current list supplies the defaults. GitHub repositories come from projects attached in Carbon.
5. Press **Create issue**. The card shows the issue link, and the conversation stays open. Carbon also links the issue to this session.

This is a regular task conversation, with the same streaming, attachments, model controls, and **Stop** button. Its history and issue review are saved with the session. After creation, you can continue the conversation or click the issue link to open it on the Issues page.

Each conversation reviews one issue. Use **New issue** to start another. If the tracker creates the issue but Carbon cannot save its session link, **Retry session link** finishes linking it without creating another issue.

If another client changes the review before your edit is saved, Carbon loads the latest review and tells you that your change was not saved.

If the tracker may have created an issue but Carbon did not receive its reply, **Check creation** looks for the original issue. It does not submit another one. Check the tracker before starting a new attempt.

### Save a view

Set the current list's tracker, search, and filters, then press the **+** beside **Saved views**. Give the view a name and press **Save**.

Selecting a saved view applies it to the current list tab. Other tabs keep their own filters. If an individual issue is open, Carbon returns to an existing list, or opens a list if none remains. Use a saved view's menu to rename or delete it. Saved views are stored on this device.

### Keep separate lists in tabs

Click **New list** (+) in the top tab row to keep another issue list open. Each list keeps its own tracker and filters. Double-click a list tab to give it a name, or clear the name to return to its automatic title. Drag tabs to reorder them.

`⌘⇧[` and `⌘⇧]` move between tabs; `⌘1`–`⌘8` select by position and `⌘9` selects the last. In an opened issue's pane, click **Open full view** to give it its own tab. `⌘W` closes the current tab or issue pane where applicable.

### Pick a tracker

The Linear and GitHub marks at the start of the filter row switch between the two. You see one tracker's issues at a time, never a merged list. The same pick applies to the composer's `#` menu.

### Filter the list

| Control | Linear | GitHub |
|---|---|---|
| Scope chips | **Assigned to me** or **Created** | **Assigned to me** or **All** |
| Open or closed | Grouped by state: In Progress, Triage, Todo, Backlog, Done, Cancelled. Done and Cancelled start folded and load when you open them. | An **Open** / **Closed** switch. The list is flat, with no headings. |
| Narrow further | The filters menu (sliders icon): **Team** and **Project**. Shown only when there is more than one of either. | **Choose a repository**, then **Type** and **Label** menus for that repository. |
| Search | **Search issues**, or `⌘⇧F` to jump to it. `Escape` clears it. | Same. |
| Refresh | The circular arrow, or `⌘R`. | Same. |

GitHub shows one repository at a time. The repositories offered are your attached projects that have a `github.com` remote. Until you pick one, the page lists them for you to click. If none qualify, it asks you to attach a project with a GitHub remote.

Both lists are ordered newest first by the date the issue was filed. In Linear, priority still sorts within each state group.

A row shows the identifier, the title, labels, and a pull-request mark with its number (or a count) when a PR is linked to the issue.

### Open an issue

- Click a row to open it in the pane beside the list: description, people, labels and comments. `⌘E` closes the pane, and opens it again on the last issue.
- Use `↑` and `↓` to move through the rows, and `Return` to open one.
- ⌘-click a row to open it in Linear or GitHub instead.
- **Work on it**, shown on a row when you hover it, takes you to an empty composer with the issue already tagged. It starts nothing until you send.

## Change status and priority

On a row, or in the opened issue's header, the status glyph and the priority glyph are menus. Click one and pick a new value. Press a digit `1`–`9` to pick that row of the menu.

- Linear: status is any state in the issue's team workflow. Priority is Urgent, High priority, Medium priority, Low priority or No priority.
- GitHub: status is open or closed, set from the opened issue. GitHub has no priority, so there is no priority menu.

A Linear key without write access cannot change either; Linear's refusal appears as a card.

## Tag an issue in a prompt

Type `#` in the composer. A menu lists your issues from the tracker that is picked. Keep typing to narrow it, then press `Return` to insert the tag.

- Under Linear the menu shows issues assigned to you.
- Under GitHub it shows every open issue in the session's own repository.

The tag goes into your text with its title, like `#DRA-53 Add issue tracker integration` or `#owner/repo#121 Add a fourth harness`. The agent reads the title. It can fetch more through its own tools — Linear's MCP server, or `gh` for GitHub.

In the sent message the tag is a button. Click it to open the issue on the Issues page. ⌘-click it to open it in the tracker.

A tag is a mention. It does not link the issue to the session.

## Issues linked to a session

When a session is linked to one or more issues, its right panel gets an **Issue** tab. Each row shows the issue with its status, description and labels. The buttons on a row remove the link from the session (the issue itself is untouched) or open the issue in the browser.

The tab appears only once something is linked, and goes away when the last link is removed.

### How issues get linked

Linking is done by the agent, or by you from a terminal, with the `carbon` CLI:

```bash
carbon issue link DRA-53 --title "Add issue tracker integration" --url "https://linear.app/…"
carbon issue link owner/repo#12 --title "…" --url "…"
```

A GitHub issue is always named `owner/repo#123`; a bare `#123` is refused, because a number alone names no repository. `carbon session new --issue DRA-53` links an issue to a session as it is created. All the commands and flags are on [Issues in the CLI](/cli/issues).

## Limits

- Carbon creates issues with a title, description, and destination. After creation, status and priority can be changed here; other fields are edited in the tracker.
- The `carbon` CLI links issues and can post Linear comments and change Linear status. Issue creation uses the app's **New issue** flow.
- The connection is workspace-wide. There is no mapping from a project to a Linear team.
- GitHub Projects are not read, and GitHub has no priority.
- GitHub Enterprise hosts are not supported.
- Shortcuts here (`⌘I`, `⌘⇧F`, `⌘R`, `⌘E`) can be changed in Settings → Shortcuts.
