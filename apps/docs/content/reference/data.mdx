Carbon keeps everything on your machine, in one folder: `~/.carbon`. Transcripts, the session list, attachments, settings and the browser's profiles all live there. A Linux server keeps its own `~/.carbon` with the sessions that run on it.

The folder is readable by your user alone, and Carbon uploads none of it. For what does leave the machine, see [Privacy](/reference/privacy).

## What's in ~/.carbon

| Path | What it holds |
|---|---|
| `sessions/<session-id>.jsonl` | One file per session: the whole transcript, one event per line. The only copy Carbon keeps. |
| `sessions/index.json` | The session list: each session's title, project, working directory, agent, model and flags. |
| `attachments/<session-id>/` | A copy of every image you sent in that session, so the transcript still shows it after you delete the original. Other files are not copied; the prompt names them by path. |
| `drafts.json` | Tasks you saved with `⌘S` and have not started. |
| `projects.json` | Attached projects, and which one was last selected. |
| `settings.json` | The analytics install id, your dictation model and microphone, the Linear account name, and whether Remote access is on. |
| `credentials.json` | Your Linear API key and the tokens for servers you added by address. Readable by your user alone (`0600`). |
| `servers.json` | The remote servers in Settings → Servers: name, address, channel. Tokens are in `credentials.json`, not here. |
| `models/` | Dictation models you downloaded in Settings → Transcription. |
| `recordings/` | Dictation audio, kept only while a transcription failed so you can retry it. Removed once the model answers, and pruned after 7 days. |
| `browser/<session-id>/` | Each session's browser profile: cookies, cache, history. |
| `browser/recordings/<session-id>/` | Videos an agent recorded of a session's browser. |
| `cef/<version>/` | The Chromium framework Carbon's browser runs on, downloaded after the first launch. |
| `chromium/` | The headless browser `carbon browser` drives where the app's own browser is not open, such as on a Linux server. |
| `pi-sessions/` | pi's own transcript of each pi session, which is how pi resumes it. |
| `opentunnel/`, `tunnel-url` | The identity behind your Remote access and share addresses, and the current address. Deleting `opentunnel/` gives you new addresses. |
| `serve-token` | The token other Macs use to reach this one through Remote access (`0600`). |
| `serve-port`, `serve.lock`, `carbon.sock` | The running server's port, its lock, and the socket the `carbon` command talks to. |
| `server.log` | The background server's log. See [Troubleshooting](/reference/troubleshooting). |
| `parse_failures.jsonl` | Lines from an agent CLI that Carbon could not read, with the raw line. Safe to delete. |
| `cli-synced` | The app version that last updated your `carbon` CLI. |

Your composer picks, theme, shortcuts, spaces list and other app preferences are not in `~/.carbon`. They live in the app's own storage on this Mac.

Outside `~/.carbon`, Carbon also writes:

- **Worktrees**, inside the project: `<project>/.claude/worktrees/<name>`, on a branch `worktree-<name>`. See [Worktrees](/using-carbon/worktrees).
- **The login item** that starts the background server: `~/Library/LaunchAgents/com.yogesh.carbon.server.plist`. The app writes it on every launch.
- **The `carbon` CLI**, if you installed it: `~/.local/bin/carbon`, and its skill in `~/.claude/skills/carbon/` and `~/.codex/skills/carbon/`.

## What goes when you delete a session

Deleting a session removes, from this machine:

- its transcript and its row in the session list,
- its attachments,
- its browser profile and any browser recordings,
- pi's copy of the conversation, for a pi session,
- its worktree and the worktree's branch, if it had one,
- any hidden sessions it started that only appear in its crew.

It does not remove the agent's own record of the conversation. Claude Code, Codex, fx and Grok Build keep their own transcripts in their own folders (below). A pushed branch and any pull request stay on GitHub.

**Settling** a session is not deleting it. Settle stops it and removes its browser profile, so it starts signed out of websites if you unsettle it. The transcript, attachments and worktree stay until you delete the worktree or the session. See [Sessions](/using-carbon/sessions).

## Environment variables

You rarely need these. Set them in the environment that launches Carbon or the `carbon` command. The Mac app opened from the Dock or Finder does not read your shell's variables, so start it from Terminal to use one:

```bash
CARBON_HOME=~/carbon-test /Applications/Carbon.app/Contents/MacOS/carbon
```

The app passes `CARBON_HOME` and `CARBON_NO_ANALYTICS` on to the background server it starts.

| Variable | Read by | What it does |
|---|---|---|
| `CARBON_HOME` | App, server, `carbon` | Uses another folder instead of `~/.carbon`, with its own sessions, settings and socket. Two Carbon servers must never share one folder: each overwrites the other's session list. On a Mac, the browser profiles and Chromium stay in `~/.carbon` either way. |
| `CARBON_NO_ANALYTICS` | App, server | Turns analytics off for that run, and is the only way to. Any value counts, even `0`. See [Privacy](/reference/privacy). |
| `CARBON_ENDPOINT` | `carbon` | Which Carbon the CLI talks to: a socket path. Carbon sets it for every agent it runs, so an agent's `carbon` calls reach the right app. |
| `CARBON_SESSION_ID` | `carbon` | The session the CLI acts for. Carbon sets it for every agent it runs. |
| `CARBON_CHANNEL` | `install.sh` | `stable` (default) or `beta`. Which releases the installer picks. |
| `CARBON_VERSION` | `install.sh` | Install one exact release tag instead of the newest. |
| `CARBON_INSTALL_DIR` | `install.sh` | Where the binaries go. Default `~/.local/bin`. |

`carbon update` keeps the channel of the version you have. Use `carbon update --channel beta` or `--channel stable` to move. See [the carbon CLI](/cli).

## Where agents keep their own data

Carbon runs each agent's own CLI and does not store agent logins. Each agent keeps its sign-in, settings and transcripts in its own folder:

| Agent | Folder |
|---|---|
| Claude Code | `~/.claude` (transcripts in `~/.claude/projects`) |
| Codex | `~/.codex` |
| pi | `~/.pi/agent` |
| fx | `~/.fx` |
| Grok Build | `~/.grok` |
| GitHub CLI | `gh`'s own config. Carbon uses it for pull requests and GitHub issues and stores no GitHub token. |

Signing in from Settings → Accounts runs the agent's own login, so the credential lands in that agent's folder. Two exceptions write there on your behalf:

- **pi:** an API key you add in Accounts is written to `~/.pi/agent/auth.json`, pi's own store.
- **fx:** Carbon sets `fast_mode` and `session_titles` in `~/.fx/settings.json` when it creates an fx session. That file is fx's global setting, so it also changes what your fx terminal uses.

See [Accounts](/settings/accounts).

## Limits

- Nothing cleans up `parse_failures.jsonl`; it grows until you delete it.
- A dictation model removed from Carbon's list in a later version stays in `models/` with no button to delete it. Delete the file by hand.
- If removing a worktree fails while deleting its session, the folder stays behind. Remove it with `git worktree remove <path>` in the project.
- There is no export. To back up, copy `~/.carbon`.
