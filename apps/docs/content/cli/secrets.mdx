`carbon secret` lets an agent request credentials without asking you to paste them into chat. The request card shows the agent, purpose, and exact destination. Enter the values in its masked fields, then approve or deny the operation.

## Commands

```bash
carbon secret command --purpose "Deploy this project" --field VERCEL_TOKEN -- vercel deploy
```

Carbon runs the shown command in the session's working directory with the value in its environment. The value never appears in the command's arguments. The request returns immediately with an ID; `carbon secret status <id>` reports the outcome and redacted output.

## Files

```bash
carbon secret file --purpose "Run a migration" --field DATABASE_URL --path .env.local -- migrate --env-file '{secret_file}'
```

By default, Carbon writes an owner-only temporary dotenv file outside the checkout, runs the command, and deletes the file. `{secret_file}` in an argument expands to its path. The command also receives `CARBON_SECRET_FILE` with that path.

The card offers **Keep in this file** for the shown checkout path. Kept files must be ignored by git, and existing files are never replaced. A file request without a command requires this explicit keep choice. Dotenv quoting is intended for an env-file reader; do not source the file as shell code.

## Browser login

```bash
carbon secret browser --purpose "Sign in" --field PASSWORD --origin https://example.com --selector 'PASSWORD=input[name=password]' --submit 'button[type=submit]'
```

The page must already be open in the session's browser. Carbon checks the HTTPS origin, document, selectors, and POST form destination before filling and submitting. A changed page or form requires a new approval. You handle any MFA or CAPTCHA. A successful hand-off means the form was submitted; it does not confirm that sign-in succeeded.

## Lifetime and protection

Requests expire after ten minutes. Commands have a five-minute limit. Each approval runs once, and a retry needs a new request. Use `carbon secret cancel <id>` to withdraw a pending request.

Carbon keeps raw values out of request metadata and saved transcripts. It redacts exact values and their JSON-escaped forms from returned command output. It discards its own copy after use and stores no reusable vault entry.

This prevents accidental exposure. It does not isolate a secret from an agent with unrestricted shell or browser access, or prevent the approved program or page from exposing it. Keeping a file leaves its value on disk. Discarding Carbon's copy does not revoke an API key or end a browser login.
