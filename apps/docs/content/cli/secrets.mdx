`carbon secret` lets an agent request credentials without asking you to paste them into chat. The request card shows the agent, purpose, and exact destination. Enter the values in its masked fields, then approve or deny the operation.

Check `carbon secret --help` before using this group with an older installation. Both the CLI and the server handling the session must support secret hand-offs.

## Request fields

`command`, `file` and `browser` share these flags:

| Flag | What it does |
|---|---|
| `--purpose <text>` | Required. Explain why the operation needs the secret. |
| `--field <NAME[=label]>` | Required. Repeat for each value. `NAME` is a variable name; the optional label is shown on the card. Never put a secret value here. |
| `--session <id>` | The session making the request. Defaults to the session running the command. Required from your own terminal. |

Put the approved program and its arguments after `--`. Carbon passes them as separate arguments; shell expressions need an explicitly named shell. Values come only from the private card, with no CLI flag or standard-input prompt for them. All secret commands return JSON.

## Commands

```bash
carbon secret command --purpose "Deploy this project" --field VERCEL_TOKEN -- vercel deploy
```

Carbon runs the shown command in the session's working directory with the value in its environment. The value never appears in the command's arguments. The request returns immediately with an ID; `carbon secret status <id>` reports the outcome and redacted output.

## Files

```bash
carbon secret file --purpose "Run a migration" --field DATABASE_URL --path .env.local -- node '--env-file={secret_file}' scripts/migrate.mjs
```

By default, Carbon writes an owner-only temporary Node-compatible dotenv file outside the checkout, runs the command, and deletes the file. `{secret_file}` in an argument expands to its path. The command also receives `CARBON_SECRET_FILE` with that path.

The card offers **Keep in this file** for the shown checkout path. Kept files must be ignored by git, and existing files are never replaced. A file request without a command requires this explicit keep choice. This format is intended for Node-compatible env-file readers; do not source the file as shell code. Carbon refuses values containing carriage returns or quote combinations that cannot round-trip through dotenv. Use command environment injection for those values.

## Browser login

```bash
carbon secret browser --purpose "Sign in" --field PASSWORD --origin https://example.com --selector 'PASSWORD=input[name=password]' --submit 'button[type=submit]'
```

The page must already be open in the session's browser. Carbon checks the HTTPS origin, document, selectors, and POST form destination before filling and submitting. A changed page or form requires a new approval. You handle any MFA or CAPTCHA. A successful hand-off means the form was submitted; it does not confirm that sign-in succeeded.

`--origin` must be an exact HTTPS origin, without a path or credentials. Repeat `--selector NAME=CSS_SELECTOR` for each requested field, then use `--submit <css-selector>` for the form's submit button.

## Check or cancel a request

```bash
carbon secret status <request-id>
carbon secret cancel <request-id>
```

`status` returns the outcome and redacted output. `cancel` withdraws a request that has not started. Both accept `--session <id>` and otherwise use the calling session.

Use `--machine <name>` for a session on another connected machine, or pass its id with `--session` to find the machine automatically. See [Work on another machine](/cli/servers#work-on-another-machine).

## Lifetime and protection

Requests expire after ten minutes. Commands have a five-minute limit. Each approval runs once, and a retry needs a new request. Use `carbon secret cancel <id>` to withdraw a pending request.

Carbon keeps raw values out of request metadata and saved transcripts. It redacts exact values and their JSON-escaped forms from returned command output. It discards its own copy after use and stores no reusable vault entry.

This prevents accidental exposure. It does not isolate a secret from an agent with unrestricted shell or browser access, or prevent the approved program or page from exposing it. Keeping a file leaves its value on disk. Discarding Carbon's copy does not revoke an API key or end a browser login.

## Limits

- A request can contain at most 16 fields.
- A request needs an unarchived Carbon session with an available working directory, and the user's approval before it runs.
- A running hand-off cannot be withdrawn with `cancel`.
- Values are not saved as reusable credentials. A retry needs a new request and approval.
