`carbon issue link` records that a session's work is against an issue. A tagged session gets an **Issue** tab in its right panel, showing that issue. Agents use it once they know which issue they are working on; you can run it yourself too.

## Link an issue

```bash
carbon issue link DRA-53 --title "Add the issue panel" --url https://linear.app/acme/issue/DRA-53
```

Prints every issue the session now carries, one per line: identifier, title and address.

Run from inside a session, it tags that session. From your own terminal, name the session with `--session`:

```bash
carbon issue link DRA-53 --session 0198f0a2-1c5e-7000-8000-000000000000
```

You can also put the session id first, before the issues. Name the session one way, not both.

Several issues at once:

```bash
carbon issue link DRA-53 DRA-54
```

| Flag | What it does |
|---|---|
| `--session <id>` | The session to tag. Defaults to the session running the command. |
| `--title <title>` | The issue's title, so the tag reads as more than an identifier. |
| `--url <url>` | The issue's web address, so the tag becomes a link. |

`--title` and `--url` describe one issue, so they are refused when you name several.

### Identifiers

| Tracker | Form | Example |
|---|---|---|
| Linear | Team key and number | `DRA-53` |
| GitHub | `owner/repo#number` | `matthieu-pm/carbonhq#255` |

A bare `#255` is refused. A number alone names no repository, so Carbon will not guess one.

## Remove an issue

```bash
carbon issue unlink DRA-54
```

Takes the issue off the session and prints what is left. The issue itself is untouched. It takes the same `--session` flag and forms as `link`.

## What linking asks the tracker

Nothing. `carbon issue link` writes down what you give it, so it works without a connected tracker and without a network. Without `--title` and `--url`, the tag is the bare identifier and links nowhere.

Two other ways to tag do look the issue up, and need the tracker connected in the app: `--issue` on [`carbon session new`](/cli/sessions#start-a-session), and an identifier written into a prompt, like `#DRA-53`. If the lookup fails, the session still runs and the tag stays plain text.

## Comment on a Linear issue

```bash
carbon issue comment CBN-53 "The retry fix is ready for review."
```

Posts the quoted text as a comment. This uses the Linear connection in Carbon's settings. The key stays in Carbon; you do not pass it to the command. No calling session or `--session` is needed.

## Change a Linear issue's status

```bash
carbon issue status CBN-53 "In Progress"
```

Moves the issue to a status its team already has. Quote names containing spaces. Names ignore letter case and repeated spaces. You can also use `triage`, `backlog`, `unstarted`, `started`, `completed` or `canceled` (`cancelled` also works) when exactly one status has that kind. Unknown or ambiguous matches are refused. Neither `comment` nor `status` links the issue to a session; use `link` for that.

To use another machine's Linear connection, pass `--machine <name>`. See [Work on another machine](/cli/servers#work-on-another-machine).

## Limits

- `comment` and `status` write to Linear only. They need Linear connected in Carbon. For GitHub writes, use GitHub or `gh`.
- The CLI does not create issues, read their full descriptions, or set assignees, labels or priorities.
- Comments must contain text and can have at most 50,000 characters.
- A tag is a copy. If the issue's title changes in the tracker, the tag keeps the old one until you link it again.
