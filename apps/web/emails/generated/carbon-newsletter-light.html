Carbon 0.30 is in beta. A rail for everything that isn’t a session, remote MCP servers, and a summary that stays put.

Four betas in two weeks. Here is what changed, one feature up close, and a few ways people are running more than one agent at once.

What shipped · 0.30.0-beta.1–4

■  New

Navigation rail. Home, Issues, usage and Settings get their own rail, with Back and Forward.

Remote MCP servers. Add and manage them from Settings.

■  Improved

Context breakdown. See what fills a Claude Code session’s context window.

Appearance. Interface and code font sizes are set separately.

Issue details. Linear issues show relations, sub-issues and cycles.

■  Fixed

Mac connection after install. The background server no longer points at an ejected disk image.

Tabs. Keep their state when switching views.

Up close

GIF · summary docks as a rail

The pinned summary, docked.

Close the right panel and the summary docks beside the chat as a full-height rail. Open it again and the summary floats as a card. Either way the chat stays where it was.

It now carries the agent’s task list and, for Claude Code, what fills the context window: messages, tools, system prompt, skills, memory and the room left.

How the summary works

Workflow

Three ways to fan out.

01

Hand a review to another agent.

A second session starts from this one’s branch and sends its findings back.

carbon session new --base <id> --harness codex

02

Let the agent look at the page.

Every session has its own browser. The agent opens, reads and clicks it like you would.

carbon browser open http://localhost:3000

03

Park a task for later.

Drafts keep the prompt and every pick, and wait in the sidebar until you start them.

carbon draft new "Move settings to the rail"
